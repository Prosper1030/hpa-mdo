# AVL Geometry And Envelope Consistency Audit

## Short Answer

The 1.565775 root/mid1 Cl requirement is expected from the current archive grading-envelope logic, not from a detected Policy C AVL geometry/input bug. The archive envelope is built once from the candidate's baseline loaded-shape AVL `station_table` before sidecar airfoil combinations are rerun. Policy A/B/C actual sidecar Cl distributions are then recomputed by AVL after replacing section AFILEs, so they can be lower than the conservative archive envelope.

## Archive Grading Envelope Construction

- Builder: `src/hpa_mdo/airfoils/sidecar.py::build_zone_envelopes`.
- Caller: `scripts/birdman_spanload_design_smoke.py::_attach_airfoil_sidecar_shadow_fields`.
- Input station source: `record["station_table"]` from the selected loaded-shape AVL reference candidate.
- Zone definitions: fixed sidecar zones root `[0.00,0.25)`, mid1 `[0.25,0.55)`, mid2 `[0.55,0.80)`, tip `[0.80,1.00]`.
- Re envelope: station `Re`, `reynolds`, or `avl_reynolds`; if absent, chord and mission contract speed/density/viscosity are used.
- Cl envelope: AVL actual local Cl only, from `cl_actual_avl`, `avl_local_cl`, or `avl_cl`.
- Fourier target Cl: stored only as a diagnostic (`max_fourier_target_cl`, `target_vs_actual_cl_delta`), not used as the archive `cl_max` field.
- Full-polar archive grading later uses `max(cl_max, cl_p90, max_avl_actual_cl, max_fourier_target_cl)` as required Cl, so the archive can be conservative in zones where either the baseline AVL actual or target curve is higher.

For this candidate, archive `cl_max` reaches 1.558129 in root and 1.565775 in mid1 because the baseline fixed-seed loaded AVL station table has those inboard local Cl values. Those are not Policy C's post-sidecar AVL values.

## Actual Sidecar AVL Computation

- Evaluator: `scripts/birdman_spanload_design_smoke.py::_evaluate_airfoil_sidecar_combination`.
- AVL writer: `src/hpa_mdo/concept/avl_loader.py::write_concept_wing_only_avl`.
- Geometry input: station `y_m`, `chord_m`, `ainc_deg`/`twist_deg`, and station `dihedral_deg` from the selected record.
- Z coordinates: generated by integrating station dihedral; the AVL summary reports `loaded_shape_source=avl_section_z_from_wing_station_dihedral`.
- Trim condition: wing-only AVL trim at the archived mission cruise speed 6.600000 m/s and mission required CL. In this audit the computed `cl_required` is 1.168531, and the Policy C trim CL is 1.168530.
- Local Cl extraction: AVL strip forces are resampled back to the same station table, then `integrate_profile_drag_from_avl` consumes those rerun local Cl values.
- Raw Policy A/C AVL files were generated transiently for this audit and parsed into `avl_geometry_policy_A.csv` and `avl_geometry_policy_C.csv`; the CSVs preserve the transient case path and all section data.

## Reference And Geometry Checks

- `Sref/Bref/Cref` are identical for Policy A and Policy C: 33.420058 m2 / 34.332286 m / 0.985106 m.
- Policy C section Z ranges from 0.000000 m to 1.050582 m; AVL summary loaded tip Z is 1.050582 m.
- Policy C root-to-tip incidence changes from 2.000000 deg to 0.016347 deg, giving about 1.983653 deg of washout.
- Policy C chord ranges from root 1.258585 m to tip 0.645934 m, with outboard/mid2 local chord up to 0.944285 m.
- All Policy A and Policy C section AFILE paths match the selected zone assignment paths in the parsed AVL geometry CSVs.

## Archive Vs Actual Interpretation

The actual Policy C root/mid1 Cl maxima are below the archive upper bound. This means DAE11's mission-grade failure against the archive envelope is stricter than the actual Policy C inboard loading. It is still logically consistent with the archive builder because the full-polar archive was graded against the baseline envelope, not rebuilt for every sidecar AVL rerun.
